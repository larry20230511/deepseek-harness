# DeepSeek Harness 技术栈分析报告

> 阅读日期：2026-09-21  
> 这份笔记回答：**各层用了什么语言、框架和工具**。产品版本快照为 `0.1.6-alpha.2`。  
> 版本以当前仓库里的 `package.json`、`vendor/README.md` 等为准；精确锁版本看 `pnpm-lock.yaml`。  
> 配套：[脚手架分析报告](./脚手架分析报告.md)（怎么组装、怎么启动）；本报告讲**技术选型**。

## 先记住这一段

- **跑程序的环境**：Node.js（22.19+ 或 24+）+ TypeScript 6；全仓库用 ES 模块。  
- **内核**：把 **Cordis** 插件框架的源码放进 `vendor/`，在仓库里维护，而不是只当普通 npm 依赖升级。  
- **界面**：服务端在 Node，浏览器端是 **Vite 6 + React 18**；桌面版用 **Electron 44** 包同一套网页。  
- **给外部程序调用**：通过标准输入输出上的 JSON-RPC（TypeScript / Python 3.10+）。  
- **会话数据**：以按行追加的 JSONL 文件为准；可选自研 Zstd 压缩；搜索和键值存储多用 Node 自带的 SQLite。

## 1. 语言与运行环境

| 项目 | 用什么 | 说明 |
| --- | --- | --- |
| Node.js | `^22.19` 或 `>=24` | CI 常以 24 为主 |
| 包管理 | pnpm `11.7.0` | 用 Corepack 对齐版本 |
| 语言 | TypeScript `^6.0.3` | 严格模式；编译目标偏新（ES2024） |
| 模块格式 | ES Module | `package.json` 里 `"type": "module"` |
| 开发时直接跑 TS | tsx | 例如 `pnpm dsh` 源码启动 |
| Python | 3.10+ | SDK 客户端；构建常用 uv、hatchling、pytest |
| 本地扩展 | Node-API 模块 | Landlock 启动器、文件锁等；安装时用预编译包，一般不现场编译 |

**两个容易混的概念：**

1. **源码直接跑**（tsx + 指向 `src`）和 **编好再跑**（`tsc` 出类型声明，`tsdown` 出运行时代码）是两套路径，不要混用假设。  
2. **服务端类型检查**和 **浏览器端类型检查**拆成两套工程（Host / Client）。因为两边都会往同一个 Cordis「上下文」类型上合并声明，合成一套会类型冲突。

## 4. 界面相关

| 部分 | 技术 | 白话 |
| --- | --- | --- |
| 网页构建 | Vite 6 + React 插件 | `apps/web` 打出前端资源，由 `dsh web` 提供 |
| UI 库 | React 18 | 浏览器端插件驱动界面；**不是** Next.js / Solid |
| 组件与样式 | 自研组件 + CSS Modules + 设计变量 | 没有绑死 Tailwind 或大型商业组件库 |
| 文档渲染 | micromark、Shiki（代码高亮）、KaTeX（公式） | 聊天等内容展示 |
| 文案国际化 | 类型化词典 + `t()` | 禁止在界面代码里写死产品文案 |
| 服务端 HTTP | 自研 `dsh-host-webserver` | 不是 Express / Koa 全家桶 |
| 桌面 | Electron 44 + electron-builder 26 | 薄壳：带上 Node 运行时和网页；Windows 用 NSIS 安装包；mac 公证；Windows 代码签名见桌面 README |
| 文档站 | VitePress + Vue 3 | 与产品网页的 Vite 6 分开 |

**界面怎么连后端：** 浏览器通过 **WebSocket** 和自研的 **Typert** 类型化 RPC、网关通信，主路径不是「一堆 REST CRUD」。

可以记成：

> Node 上的 Host（Cordis） ↔ 浏览器里的 Client（Cordis + React）

## 5. 大模型与外部协议

| 集成 | 技术 | 白话 |
| --- | --- | --- |
| DeepSeek | `dsh-llm-deepseek` | 官方对话接口适配；流式输出有解析器 |

| MCP | `@modelcontextprotocol/client` 2.0 | 接外部工具服务器 |

| 浏览器 / 电脑操作 | Playwright、各类 MCP / 驱动（多在实验组） | 可选能力 |

真实 API 测试需要环境变量 `DEEPSEEK_API_KEY`（可选 `DEEPSEEK_BASE_URL`）；没有 key 时相关 e2e 会跳过。

## 6. 数据怎么存

| 用途 | 技术 | 白话 |
| --- | --- | --- |
| 会话主记录 | JSONL 文件 | **给模型看的内容必须以这里为准**；文件名类似 `session.vN.jsonl` |
| 压缩 | 包内自写的 Zstd 帧 | 可选；不是再依赖一个独立的 `zstd` npm 包 |
| 并发写保护 | 系统文件锁等 | Linux/mac 用 native；Windows 另有辅助 |
| 会话搜索 | SQLite 全文检索 | 用 Node 内置 `node:sqlite`；库结构版本只增不减 |
| 其它键值数据 | SQLite 或 JSON 文件 | `packages/storage/` |
| 大段工具输出 / 附件 | 本地按内容存文件 | spill、attachment 等包 |

## 7. 命令执行与隔离

| 能力 | 技术（白话） |
| --- | --- |
| 统一接口 | 沙箱、子进程、Shell、终端、文件系统各有 `ctx.…` |
| Linux 隔离 | bubblewrap，再落到 Landlock 启动器 |
| macOS 隔离 | 系统 Seatbelt / `sandbox-exec` |
| Windows 隔离 | 受限令牌 / ACL 一类路径 |
| 交互式终端 | `node-pty`（仓库打过补丁） |
| 远程机器 | OpenSSH，并配有远程文件/进程/沙箱实现 |
| 沙箱内跑 Node 等 | PTC 相关包 |

不同操作系统能力不一样；Windows 上部分偏 Linux 的测试会被跳过。

## 8. 两套对外通信（别混）

```text
给脚本 / 其它语言：
  TS 或 Python SDK  ──标准输入输出上的 JSON-RPC──►  dsh（sdk 或 sdk-minimal）

给网页 / 桌面界面：
  浏览器  ──WebSocket + Typert──►  网关 / 网页服务
```

| 场景 | 技术 |
| --- | --- |
| SDK | 一行一条 JSON 的 RPC；Python 用 pydantic v2，并捆绑可执行的 `dsh` |
| 界面 | Typert（协议、注册表、代码生成）+ `ws` + Host 路由 |
| 普通 HTTP | 主要提供静态资源、启动注入等，不是主业务 API |

两套都要用；**SDK 不会在自己进程里再嵌一整棵插件树**，而是正式启动一个 `dsh` profile。

## 9. 怎么打包发出去

| 产物 | 怎么做 |
| --- | --- |
| npm 上的 `@deepseek-ai/dsh-*` | TypeScript 编译 + tsdown；publint；发版脚本 |
| 桌面安装包 | electron-builder；mac 公证；Windows NSIS + 代码签名；可上传对象存储 |
| Python 安装包 | hatchling；运行时用 pkg 打成单文件；**GitLab CI** 在 Python 版本标签上发 wheel |
| 本地系统模块 | 独立的 GitHub 工作流预编译多种 CPU/系统 |

日常质量检查主要在 **GitHub Actions**。GitLab 这边更偏向 Python 发布，不是日常每个 PR 的全套质量门。

## 10. 分层总览

```text
工程工具：pnpm · TypeScript · Vitest · Oxlint · Lefthook · 各类自动检查
                │
运行内核：Cordis（源码在 vendor）+ 加载器 + YAML 配置
                │
     ┌──────────┼──────────┐
     ▼          ▼          ▼
  Agent/模型   会话存储    执行与沙箱
  DeepSeek等   JSONL/SQLite  各系统隔离方案
     │
     ├─ 命令行 dsh（选 profile）
     ├─ 网页（Vite + React）
     ├─ 桌面（Electron，同一套网页）
     └─ SDK（标准输入输出 JSON-RPC → TS / Python）
```

## 11. 和常见做法差在哪

| 常见做法 | 这里怎么做 |
| --- | --- |
| Express + 自己注册插件 | Cordis：服务、事件、卸载时可撤销 |
| 一个 Next 或重写 Electron UI | 多种 profile 叠配置；桌面主要是承运已有网页 |
| Postgres + ORM 当会话真相 | JSONL 文件是真相；SQLite 多用于搜索和键值 |
| Python 进程里直接跑 Agent | Python 只启动捆绑的 `dsh` 子进程 |
| 直接依赖上游 Cordis npm | 源码放进仓库并维护本地补丁清单 |
| 覆盖率较松 | 对核心源码包要求按文件高覆盖 |
