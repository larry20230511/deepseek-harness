# DeepSeek Harness 运行模式分析报告

> 阅读日期：2026-09-21  
> 这份笔记列出**所有受支持的运行模式**，以及每种模式的**详细启动方式**（命令、常用参数、怎么停）。  
> 依据：`apps/cli/README.md`、`apps/cli/reference/README.md`、`apps/cli/src/args.ts`、各 `packages/bundle/*/README.md`、`apps/desktop/README.md`、根 `README.md` / `package.json`。  
> 性质：解读笔记，非产品权威。

## 先记住这一段

正式跑产品，几乎都要经过同一个命令：**`dsh`**（npm 包 `@deepseek-ai/dsh`）。  
「运行模式」在仓库里主要体现为命名的 **profile**（白话：启动形态 / 配置组合）。

| 编号 | 运行模式 | profile 名 | 一句话 |
| --- | --- | --- | --- |
| 1 | 网页界面 | `web` | 本机开浏览器聊天 |
| 2 | 无界面一次任务 | `headless` | 命令行跑完一件事就退出 |
| 3 | SDK 完整服务 | `sdk` | 标准输入输出上的 JSON-RPC，给程序调用 |
| 4 | SDK 最小服务 | `sdk-minimal` | 更瘦的 SDK 树，给示例/嵌入用 |
| 5 | ACP 自动化 | `acp` | 标准输入输出上的 ACP 协议 |
| 6 | 桌面应用 | `desktop`（内部名） | Electron 安装包 / 开发启动；**不能**用 `dsh desktop` |
| 7 | 自定义 profile | 你起的名字 | 从出厂模板拷贝后再改 |

下面先写**三种拿到 `dsh` 的方式**，再按模式写启动命令。

---

## 0. 怎么拿到 `dsh`（三种入口）

| 入口 | 命令写法 | 说明 |
| --- | --- | --- |
| 临时跑（推荐试玩） | `npx @deepseek-ai/dsh …` | 不必全局安装 |
| 已安装 CLI | `dsh …` | `npm i -g @deepseek-ai/dsh` 或等价安装后 |
| 本仓库源码 | 先 `pnpm run build`，再 `pnpm dsh …` | 开发/fork；`pnpm dsh` 走 TypeScript 入口 |

Python 安装 `deepseek-harness-sdk` 后，运行时 wheel 里也会带同名 `dsh`，但 **必须显式设置 `DSH_HOME`**，不会默认用 `~/.dsh`。

### 启动器自己认识的参数（写在最前面）

```text
dsh [启动器参数…] [profile 简写或 --profile 名] [该模式自己的参数…]
```

| 启动器参数 | 作用 |
| --- | --- |
| `--profile <名>` 或 `dsh <名>` | 选哪个启动形态 |
| `--from-default-profile <模板>` | 用出厂模板新建一个自定义 profile，再启动 |
| `--patch <文件>` | 可重复；叠额外配置补丁 |
| `--dump-config` | 只打印最终会装哪些插件，**不真正启动** |
| `--dump-default-config` | 只打印出厂组合层，不带用户补丁 |
| `-V` / `--version` | 版本 |
| `dsh --help` | 启动器帮助；`dsh web --help` 才是网页模式自己的帮助 |

注意：启动器不认识的第一个参数开始，都交给「当前模式」解析。  
例如：`dsh web --port 8080` 里的 `--port` 属于网页模式，不是启动器。

### 常用环境变量（多数模式共用）

| 变量 | 作用 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 调 DeepSeek 模型时常需要 |
| `DEEPSEEK_BASE_URL` | 可选，改模型网关地址 |
| `DSH_HOME` | 数据与 profile 目录；默认多为 `~/.dsh`；Python 自带的 `dsh` **必须**显式指定 |
| `DSH_TELEMETRY_DISABLED` / `DSH_TELEMETRY_MODE` | 遥测开关（见遥测报告） |
| `HTTP_PROXY` / `HTTPS_PROXY` 等 | 出站代理（遥测故意不走代理） |

调用目录下的 `.env`、以及 `$DSH_HOME/.env` 等会按规则加载（细节见 CLI reference）。

### 怎么停

| 情况 | 做法 |
| --- | --- |
| 长驻服务（web / sdk / acp） | `Ctrl+C`（SIGINT）或发 SIGTERM；一般会先尽量收尾再退出 |
| headless | 任务结束自己退出；也可 `Ctrl+C` 打断 |
| 桌面 | 退出应用 / 关窗口 |

## 1. 网页界面（`web`）

**干什么：** 在本机起 HTTP 服务，用浏览器聊天、改设置、看会话。默认地址大致是 `http://127.0.0.1:3080`。

### 启动命令

```sh
# 试玩
npx @deepseek-ai/dsh web

# 已安装
dsh web
dsh --profile web

# 源码仓库
pnpm run build
pnpm dsh web
```

### 常用参数（网页模式自己的）

```sh
dsh web --no-open                 # 只打印 URL，不自动开浏览器
dsh web --port 8080               # 改端口；0 表示让系统分配空闲端口
dsh web --host 127.0.0.1          # 绑定主机（默认本机环回）
dsh web --trusted-host example.com   # 可重复；额外允许的 Host
dsh web --help                    # 网页模式帮助
```

**明确不支持：** `--host 0.0.0.0`（出于安全，启动会直接报错）。

### 叠加配置示例

```sh
# 可选示例补丁（默认 profile 不含这些）
pnpm dsh web --patch apps/cli/config/examples/schedule/cordis.yml
pnpm dsh web --patch apps/cli/config/examples/github-review/cordis.yml

# 仓库演示：带 inspector 补丁
pnpm run demo:inspector
```

### SSH 上跑网页时

在远端执行 `dsh web`（常自动带 `--no-open` 行为：不弹远端浏览器），把打印的 `127.0.0.1` URL 用 SSH 端口转发到本地再打开。

### 成功长什么样

终端出现 `dsh web: http://…` 一行；浏览器能打开并配置模型后可对话。源码环境若前端未构建，会提示先 `pnpm run build`。

## 2. 无界面一次任务（`headless`）

**干什么：** 命令行交给 Agent 一件事，把最终答案打到标准输出，然后进程结束。不开网页、不监听给浏览器用的端口。

### 启动命令

```sh
# 任务写在参数里
dsh headless "总结当前目录的主要包"
dsh --profile headless "run the tests"
pnpm dsh --profile headless "run the tests"
npx @deepseek-ai/dsh headless "run the tests"

# 任务从管道读入
{ echo "Summarize these changes:"; git diff --stat; } | dsh --profile headless

# 仓库演示：强制 PTC 工具模式后再跑 headless（需 API key）
pnpm run demo:ptc -- "task"
```

通常需要：`DEEPSEEK_API_KEY`。

### 常用参数

```sh
dsh headless "任务" --json              # 标准输出改为按行 JSON 事件流
dsh headless "任务" --session-id <id>   # 指定/续用会话 id；未知 id 会失败
dsh headless -                          # 显式从 stdin 读任务
dsh headless --help
```

规则要点：

- 有位置参数任务时，**不再读 stdin**；要从管道喂全文，就不要再写位置参数。  
- 空任务会被拒绝。  
- 退出码：成功完成多为 `0`，中止/出错多为 `1`。  
- 推理过程可能打在 stderr（`dsh: reasoning:`）；最终答案在 stdout。

## 3. SDK 完整服务（`sdk`）

**干什么：** 在标准输入输出上提供 JSON-RPC，让 TypeScript / Python 等客户端驱动完整 Agent 能力（叠在共用底座上）。

### 手工启动（少见，调试用）

```sh
dsh --profile sdk
pnpm dsh --profile sdk
npx @deepseek-ai/dsh --profile sdk
```

正常用法是**客户端帮你拉起**这个进程，而不是人手在终端里挂着。

### TypeScript 客户端（示意）

```ts
// 依赖 @deepseek-ai/dsh-sdk-client，并保证同版本 @deepseek-ai/dsh 可用
new DeepSeekHarness({
  profile: 'sdk',
  // dshBin?, dshHome?, patches? …
})
```

### Python 客户端（示意）

```sh
pip install deepseek-harness-sdk
export DSH_HOME=/绝对路径/到/数据目录   # 必需
export DEEPSEEK_API_KEY=...
```

```python
DeepSeekHarness(
    dsh_home="/绝对路径/到/数据目录",
    cwd="/绝对路径/到/工作区",
    # provider / model …
)  # 默认 profile 为 sdk
```

### 参数与退出

- CLI 侧几乎没有「业务 flags」；协议在 stdio。  
- `dsh --profile sdk --help` 只打印帮助，不占用协议通道。  
- 停止：协议 `shutdown`、stdin 结束、或信号；客户端 `close()` 会按 EOF → SIGTERM → SIGKILL 一类顺序收尾。

**注意：** Python/TS SDK **不能**把 `web` 当服务 profile（网页没有这套 JSON-RPC）。

---

## 4. SDK 最小服务（`sdk-minimal`）

**干什么：** 故意不叠共用底座，树更短：适合最小示例、可控嵌入。权限更开放（文档写明固定偏「全权」一类策略），请用可丢弃目录。

### 启动命令

```sh
export DSH_HOME=/绝对路径/到/数据目录
dsh --profile sdk-minimal
pnpm dsh --profile sdk-minimal
```

### Python 最小示例（仓库内）

```sh
export DEEPSEEK_API_KEY=...
python python/sdk/examples/minimal.py \
  --dsh-home /绝对路径/home \
  --workspace /绝对路径/ws \
  --session-id example-001 \
  "task"
```

（示例脚本还可能认 `DSH_MODEL`、`DEEPSEEK_BASE_URL` 等，以 `python/sdk/examples/README.md` 为准。）

### TypeScript

客户端里指定 `profile: 'sdk-minimal'` 即可（细节见 SDK client README）。

停止方式与 `sdk` 相同。

---

## 5. ACP 自动化（`acp`）

**干什么：** 按 Agent Client Protocol 在 stdio 上服务自动化客户端（创建/恢复会话、发 prompt 等）。不是给人点的网页。

### 启动命令

```sh
dsh --profile acp
pnpm dsh --profile acp
npx @deepseek-ai/dsh --profile acp
```

外部 ACP 客户端或仓库内的 ACP 子 Agent 提供方，通常会自己 `spawn`：`dsh --profile acp`。

### 参数与退出

- 无额外 CLI 业务 flags；stdout 专供协议。  
- 停止：对端断开、stdin EOF、或信号。

---

## 6. 桌面应用（内部 profile：`desktop`）

**干什么：** Electron 壳 + 完整网页能力。数据目录独占 `$DSH_HOME/profiles/desktop`。默认本机端口常为 **19387**（可被配置覆盖）。

### 用户怎么启动

1. 从 `download.deepseek.com`（或测试站）安装 Windows / macOS 安装包。  
2. 从开始菜单 / 应用图标 / 安装完成页启动。  

**不要**执行：`dsh desktop` 或 `dsh --profile desktop`（CLI 会拒绝：该 profile 仅 Electron 管理）。

### 开发者怎么启动（本仓库）

```sh
pnpm run dev:desktop     # 构建并启动 Electron
pnpm run start:desktop   # 已有构建产物时跳过部分构建再启
```

开发默认数据目录在 `apps/desktop/.desktop-build/development/home`；可用 `DSH_HOME` 覆盖其中 Harness home。  
调试相关：`DSH_DESKTOP_MAIN_INSPECT_PORT`、`DSH_DESKTOP_RENDERER_DEBUG_PORT`、`DSH_DESKTOP_HOST_INSPECT_PORT`、`DSH_DESKTOP_OPEN_DEVTOOLS=0`（见 Desktop README）。

### 停止

退出应用；自动更新安装时会停 Host 再拉起。

## 7. 自定义 profile

**干什么：** 用出厂模板生成一个新名字的启动形态，再装插件或打补丁。

出厂模板名只有：`web`、`headless`、`sdk`、`sdk-minimal`、`acp`。  
名字 `desktop` 不能用 CLI 创建/启动。

### 从模板创建并启动

```sh
# 例如：从 web 模板新建名为 rescue 的 profile，并启动
dsh rescue --from-default-profile web
dsh --profile rescue --from-default-profile web --port 8080
```

### 用插件管理初始化 / 装包后启动

```sh
dsh plugin --profile myapp add <某插件包>
dsh --profile myapp
dsh --profile myapp --patch ./extra.yml
```

自定义 profile 继承「模板对应模式」的参数（从 web 模板来的就认 `--port` 等；从 headless 来的就认任务参数等）。

## 8. 管理与检查命令（不是「运行模式」，但常一起用）

| 命令 | 干什么 |
| --- | --- |
| `dsh plugin --profile <名> add/remove/update …` | 在该 profile 目录里转发 pnpm 管插件（需本机有 pnpm） |
| `dsh --profile web --dump-config` | 看最终插件树，不启动 |
| `dsh --profile web --dump-default-config` | 只看出厂组合层 |
| `dsh -V` | 版本 |
| `pnpm run dev:web` | **只**盯前端构建/热更新，**不是**启动完整 `dsh web` 应用 |

若有人起了一个真名叫 `plugin` 的 profile，要用 `dsh --profile plugin` 启动；单独写 `dsh plugin` 会进管理子命令。

## 9. 对照总表（复制用）

| 模式 | 最短启动 | 典型停法 |
| --- | --- | --- |
| 网页 | `npx @deepseek-ai/dsh web` | Ctrl+C |
| 无界面 | `dsh headless "任务"` | 自己退出 / Ctrl+C |
| SDK | 客户端创建 `DeepSeekHarness`（或 `dsh --profile sdk`） | shutdown / EOF / 信号 |
| SDK 最小 | `DSH_HOME=… dsh --profile sdk-minimal` | 同上 |
| ACP | `dsh --profile acp` | 断连 / 信号 |
| 桌面 | 安装包启动，或 `pnpm run dev:desktop` | 退出应用 |
| 自定义 | `dsh 名字 --from-default-profile web` | 随底层模式 |

---

## 10. 不受支持 / 容易踩坑的启动方式

| 做法 | 结果 |
| --- | --- |
| `dsh desktop` / `dsh --profile desktop` | 被拒绝 |
| `dsh web --host 0.0.0.0` | 被拒绝 |
| 用某个功能包自己的 bin 当「正式应用入口」 | 仓库检查不认；正式入口只有 `dsh` |
| 在进程里直接挂插件冒充整应用 | 不是受支持的产品启动路径 |
| Python SDK 选 `web` 当服务 | 不可用（无 JSON-RPC） |
| 没 `build` 就 `pnpm dsh web`（缺前端产物） | 可能启动失败并提示先构建 |
| `DSH_TELEMETRY_MODE=FULL` | 配置拒绝（不是运行模式，但是常见误设） |
