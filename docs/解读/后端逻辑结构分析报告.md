# DeepSeek Harness 后端逻辑结构分析报告

> 阅读日期：2026-09-21  
> 这份笔记讲：**Node 进程里的「后端」怎么分层、请求怎么走、各目录干什么**。  
> 浏览器界面细节见 [应用架构设计分析报告](./应用架构设计分析报告.md)；怎么启动见 [运行模式分析报告](./运行模式分析报告.md)。  
> 依据：`docs/architecture.md`、`docs/api-gateway.md`、`packages/api/README.md`、`packages/core/README.md`、`packages/host/README.md`、`packages/boot/app-boot/README.md`。  
> 性质：解读笔记，非产品权威。

## 先记住这一段

本仓库**没有**单独再开一套「后端微服务」。所谓后端，就是跑在 **Node 进程里的同一棵插件树**：

- 中间干活：会话、主循环、模型、工具、文件与命令；  
- 对外可以再加：HTTP 与类型化远程调用（网页）、标准输入输出上的 JSON-RPC（SDK）、ACP、或命令行一次任务。

可以记成三句话：

1. **一个进程、一棵插件树、多种外壳。**  
2. **网页多一层「门房 + 柜台」；无界面 / SDK / ACP 换协议，不换车间。**  
3. **给模型看的内容 = 已经写入会话日志的内容。**

```text
外壳（可选）
  网页 HTTP / SDK stdio / ACP / 无界面命令
        │
        ▼
业务入口（网页才有完整一层）
  远程方法调用、会话/工作区控制器
        │
        ▼
车间（所有模式共用）
  Agent → 主循环 → 模型 / 工具 → 会话日志 → 落盘
```

## 1. 「后端」在本仓指什么

| 说法 | 白话 | 主要位置 |
| --- | --- | --- |
| Host（本机服务半边） | 给浏览器开门：HTTP、认证、`/api`、静态页 | `packages/host/`、`packages/api/`、`packages/client/connection` 的 Host 半 |
| Agent 运行时 | 收输入、问模型、跑工具、写日志 | `packages/core/` + 各能力包；由 `dsh-base` 挂上 |
| 无 GUI 模式 | 仍是同一车间；表面换成一次性任务或协议服务 | `headless` / `sdk` / `acp` |

因此：Web 的「后端」= 传输与业务入口 + Agent 车间；Headless/SDK/ACP 的「后端」主要是车间 + 各自协议表面。

## 2. 进程怎么起来

```text
dsh / pnpm dsh
  → apps/cli          解析要开哪个 profile
  → dsh-app-boot      读环境变量、叠配置补丁、启动加载器
  → Cordis Loader     按配置挂插件、注入服务
  → 必需插件就绪      进程可对外服务或开始跑任务
```

配置叠法（空列表之上）：功能组合包补丁 → 当前 profile 补丁 → 用户主目录补丁 → 命令行 `--patch`。

启动时会检查「这一形态启用的必需插件」是否起来。例如：

| 形态 | 典型必需内容（概念上） |
| --- | --- |
| 网页 | 主循环、网页服务、连接、模块加载等 |
| 无界面 | 主循环、一次性任务 runner |
| SDK | 主循环、JSON-RPC 服务 |
| ACP | 主循环、ACP 服务 |

共用底座是 `dsh-base`；网页再叠 `dsh-web-app`，无界面叠 `dsh-headless`，以此类推。`sdk-minimal` 故意不叠底座。

## 3. Node 进程内怎么分层

| 层 | 干什么 | 主要目录 |
| --- | --- | --- |
| 启动胶水 | 组配置、开加载器、失败时报错、开发时热更新、插件安装 | `packages/boot/`、`apps/cli/` |
| 业务入口（网页完整） | 浏览器「打方法」、会话/工作区/设置等远程接口 | `packages/api/`、`packages/typert/` |
| 车间脊柱 | 会话日志、Agent、主循环、工具表、系统提示 | `packages/core/` |
| 模型 | 统一调用面 + DeepSeek 等适配器 | `packages/llm/` |
| 执行世界 | 文件、Shell、终端、沙箱、子进程、远程 SSH 等 | `packages/fs/`、`shell/`、`sandbox/`、`subprocess/`、`ssh/`… |
| 落盘与查询 | 会话文件、投影、搜索、其它存储 | `packages/session/`、`session-query/`、`storage/` |
| 设置与人机 | 配置、密钥、审批、斜杠命令、向用户提问 | `packages/settings/`、`credentials/`、`interaction/` |
| 可选门房 | 纯 HTTP 路由与静态页（不懂 Agent） | `packages/host/` |

依赖方向（概念上）：外壳 → 业务入口 → `ctx.agents` / `ctx.sessions` → 主循环 → 模型与工具 → 执行提供方；落盘挂在会话上。

## 4. 网页后端：门房、柜台、车间

用门店比喻（只帮助理解）：

| 角色 | 目录 | 白话 |
| --- | --- | --- |
| 门房 | `packages/host/` | 开门、递静态页、选目录、查插件清单；**不**负责一轮对话 |
| 柜台 | `packages/api/` | 会话发消息、工作区、设置、终端控制等「打一次方法」 |
| 车间 | `packages/core/` + 能力包 | 真正问模型、跑工具、写日志 |

### 4.1 门房（`host/`）

| 包 | 干什么 |
| --- | --- |
| `webserver` | 本机 HTTP：命名路由、升级、回退座位 |
| `frontend-static` | 托管编好的网页资源 |
| `directory-picker*` | 选工作区目录（系统对话框 / 页内浏览 / 自动选实现） |
| `open-in-app` | 用本机已装应用打开目录 |
| `plugin-inventory` | 只读查看当前已加载插件 |

### 4.2 柜台（`api/`）

| 包 | 干什么 |
| --- | --- |
| `gateway` | 远程调用网关：参数校验、解析会话/Agent、调用业务方法；也可管多路流 |
| `remotes` | 决定暴露哪些 Host 能力、转发哪些事件；浏览器侧统一挂接 |
| `session-controller` | 会话生命周期、发 prompt、历史跟随、控制状态 |
| `workspace-controller` | 工作区增删改与投影 |
| `settings-controller` | 设置与凭据读写 |
| `terminal-controller` | 会话内交互终端 |
| `workspace-files` | 有界的工作区文件读写与变更流 |

「打一次方法」和「会话历史流式推送」是不同通道，但共用同一套连接（认证后的 `/api` 等）。

### 4.3 类型化远程调用（Typert，白话）

1. 业务代码用注解标出「允许浏览器调用」的方法。  
2. 构建时生成调用描述。  
3. 浏览器调用 `ctx.remote.<命名空间>.方法(...)`。  
4. 经连接打到 Host 网关 → 校验 → 把 `sessionId` 等解析成活着的对象 → 调真实服务。  

复杂对象不能直接过网线，要用约定好的 id 在 Host 上再解析。细节见 `docs/api-gateway.md`。

## 5. 车间脊柱（`core/`）

| 包 | 干什么 | 常见名字 |
| --- | --- | --- |
| `session` | 只追加的会话事件日志 | `ctx.sessions` |
| `agent` | Agent 句柄、注册表、进行中事件 | `ctx.agents` |
| `agent-loop` | 默认主循环（可替换实现） | `ctx.agentLoop` |
| `tools` | 工具注册与执行流水线 | `ctx.tools` |
| `system-prompt` | 拼系统提示和工具描述 | `ctx.systemPrompt` |
| `agent-default-model` | 新会话默认模型 | `ctx.agentDefaultModel` |
| `scope` | 按 Agent 隔离注册 | 库，无固定 `ctx` 键 |

扩展代码应依赖 `agent` 接口，而不是绑死某一种主循环实现。

主循环简化：认领输入 → 拼提示 → 问模型 → 跑工具 → 写日志 → 必要时再问 → 结束这一轮。完整步骤见架构文档 Turn flow。

## 6. 一条关键路径：网页发消息再流回来

```text
浏览器：Session.prompt / remote.session.prompt
        │
        │  认证后的 POST /api（或等价连接）
        ▼
Host 网关：校验参数，用 sessionId 找到 Agent
        │
        ▼
session-controller：处理附件等 → agent.followup 或 steer
        │
        ▼
agent-loop：
  开始一轮 → 拼系统提示与工具
  → ctx.llm 流式请求
  → ctx.tools 执行（文件/命令/…）
  → 追加 user/message、assistant/message、tool/* 等事件
        │
        ├── 落盘（如 JSONL）
        └── 广播 / 投影
                │
                ▼
        历史流 + 助手增量流 → 浏览器刷新界面
```

要点：

- 流式字（`agent/assistant-stream`）主要给界面实时显示；磁盘上的权威内容是结算后的消息事件。  
- 无界面模式没有网关：runner 直接建 Agent、塞任务、把结果打到标准输出。

## 7. 各运行形态后端差在哪

| 形态 | 车间（base） | 门房 HTTP | 柜台 Remote | 对外通道 |
| --- | --- | --- | --- | --- |
| 网页 | 有 | 有 | 有 | 浏览器 |
| 桌面 | 有（同网页） | 有（进程内） | 有 | Electron 窗口连本机 Host |
| 无界面 | 有 | 无 | 无 | 命令行任务 / JSON 事件 |
| SDK | 有 | 无 | 无* | stdio JSON-RPC |
| ACP | 有 | 无 | 无* | stdio ACP |
| SDK 最小 | 自带瘦树 | 无 | 无* | 同 SDK 表面 |

\* SDK/ACP 有自己的协议服务器插件，不是网页那套 Typert Remote 柜台。

## 9. 改后端时怎么下手

| 目标 | 优先改哪里 |
| --- | --- |
| 新的模型提供方 | `packages/llm/` 适配器 + 挂到 `ctx.llm` |
| 新的模型工具 | 工具包 + `ctx.tools`；需要时补会话事件 |
| 网页新远程方法 | 业务服务标远程方法 → 进 remotes 组装 → 客户端调用 |
| 只影响一次任务的 CLI 输出 | `headless` 相关表面，不要动主循环 |
| 会话怎么存盘 | `packages/session/` 持久化实现 |
| 必须改「一步/一轮」语义 | `agent-loop`，并同步改 `docs/architecture.md` |
