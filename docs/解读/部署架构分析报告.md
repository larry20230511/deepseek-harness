# DeepSeek Harness 部署架构分析报告

> 阅读日期：2026-09-21  
> 这份笔记回答：产品**支持几种部署方式**、每种**怎么装怎么跑**、以及每种与**云端**的关系。  
> 依据：`README.md`、`docs/architecture.md`、`docs/user/guide/`、`apps/desktop/README.md`、`apps/cli/README.md`、各 profile 对应的功能组合包说明。  
> 性质：解读笔记，非产品权威；与官方文档冲突时以官方为准。

## 先记住这一段

DeepSeek Harness **不是**「把服务开到公网、多人共用一套后台」的云 SaaS。它主要是**跑在用户机器（或用户自己的远程机器）上的本机 Agent**，需要算力时再**出站访问**大模型等云服务。

当前文档与出厂配置能明确支持的部署形态有 **6 种**。另外有 **1 种常见变体**（SSH 上开网页），不算独立产品形态。

| 编号 | 部署形态 | 程序跑在哪 | 用户怎么用 |
| --- | --- | --- | --- |
| A | npm / npx 本机网页 | 本机 Node + 本机浏览器 | `npx @deepseek-ai/dsh web` |
| B | 源码本机运行 | 本机仓库编译产物 | `pnpm dsh web` 等 |
| C | 桌面安装包 | 本机 Electron 应用 | 从官网下载安装（Windows / macOS） |
| D | 无界面一次性任务 | 本机命令行，不开网页 | `dsh --profile headless "任务"` |
| E | SDK 嵌入 | 宿主程序再拉起 `dsh` 子进程 | TypeScript / Python SDK |
| F | ACP 自动化 | 本机标准输入输出 | `dsh --profile acp` |

**不算正式产品部署的：**

- 把网页服务绑到 `0.0.0.0` 对外公网监听（官方 CLI **拒绝**这种用法）  
- DeepSeek 托管的多租户「在线版 Harness SaaS」（仓库无此产品）  
- 仅「工具在 SSH 远端执行」的能力组合（可自定义配置，但不是出厂安装通道）

---

## 所有形态都会碰到的云端关系（共用）

下面这些与「用哪种入口启动」基本无关，只要装了共用底座（`dsh-base`）或仍走默认 DeepSeek 相关插件，就可能出现。

| 云端 / 远程 | 干什么 | 是否必需 | 怎么关或改 |
| --- | --- | --- | --- |
| DeepSeek 模型 API（默认 `https://api.deepseek.com`，Messages 路径常带 `/anthropic`） | 真正对话、推理 | **做任务时通常必需**（也可改成自建或其它提供方） | 界面 Settings、环境变量 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`；见 `docs/user/guide/providers.md` |
| DeepSeek 联网搜索（与模型同一类密钥体系，可另配搜索地址） | `web_search` 等工具 | 用到该工具时需要 | `DEEPSEEK_SEARCH_BASE_URL` 等 |
| 会话日志随请求上传（`session-log-deepseek`） | 把会话日志增量作为 DeepSeek 请求元数据带上 | **默认开启**，产品不依赖它才能跑 | 在 profile 补丁里设 `session-log-deepseek.enabled: false` |
| 遥测日志（默认指向 `harness-telemetry.deepseeksvc.com` 一类 OTLP 地址） | 用户反馈等场景上报；走 Node 直连，不跟代理走 | **可选**；默认偏「仅反馈」一类策略 | `DSH_TELEMETRY_MODE=DISABLED` 或 `DSH_TELEMETRY_DISABLED`；见网络代理用户指南 |
| 匿名安装标识（本机 `$DSH_HOME` 下文件） | 请求头里带用户匿名 id，便于关联反馈 | 本地生成，不是登录账号 | 删对应文件可重置 |
| npm / PyPI / GitHub 文档站 | **发布与下载安装包**，不是运行时控制台 | 安装时需要网络 | — |

**说明：**

- 「云端」在这里主要指：**模型推理云**、**可选遥测**、以及（仅桌面）**安装包与自动更新下载站**。  
- **没有**证据表明：必须登录 DeepSeek 账号才能启动本机产品；或默认把整个会话文件上传到对象存储。  
- 用户可在 Settings 里配置**自建大模型网关**（文档里的 self-hosted 指「你自己的模型服务」，不是「Harness 官方多用户服务」）。

## A. npm / npx 本机网页

### 这是什么

在本机用官方发布的命令行包启动网页界面。默认在 `http://127.0.0.1:3080`，本机浏览器打开。

### 部署方案

1. 安装 Node.js（满足引擎要求）。  
2. 执行：`npx @deepseek-ai/dsh web`（或先 `npm i -g @deepseek-ai/dsh` 再 `dsh web`）。  
3. 在界面 **Settings → Models** 填入 [DeepSeek API key](https://platform.deepseek.com/)，或设置环境变量。  
4. 选择工作区目录，开始会话。  

数据目录默认在用户机器的 Harness home（常为 `~/.dsh`）。进程只在本机环回地址提供界面；浏览器与本机服务之间用进程内认证，不是公网多用户登录。

依据：`README.md`、`docs/user/guide/index.md`。

### 云端关系

| 方向 | 内容 |
| --- | --- |
| 本机 → DeepSeek API | 对话与工具调用（密钥在本机） |
| 本机 → 可选遥测 | 反馈相关上报（可关） |
| 本机 → npm | 安装 / 升级 `@deepseek-ai/dsh` |
| DeepSeek 云 → 本机 | **无**反向控制本机进程的产品通道 |
| 对象存储 / 更新站 | **不参与**此形态的运行与升级 |

## B. 源码本机运行

### 这是什么

从 Git 仓库安装依赖、编译，再用 `pnpm dsh` 启动。和 A 是同一套产品能力，差别在「从源码构建」而不是「从 npm 装成品」。

### 部署方案

```sh
git clone <仓库>
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web          # 或 headless / sdk / acp 等
```

开发时也可不先完整 build，用源码入口（见 `apps/cli` 说明）。适合二次开发、fork、改插件。

### 云端关系

与 **A 相同**（同一套出厂 profile / 共用底座）。额外只有：拉代码、装依赖时访问 Git / npm 等。**没有**单独的「源码版更新服务器」。

---

## C. 桌面安装包（Windows / macOS）

### 这是什么

Electron 桌面壳，里面带着完整的 dsh 运行时和网页界面。用户双击安装包使用，不必自己装 Node。默认本机端口常为 `19387`（与网页版 `3080` 分开）。配置目录独占 `$DSH_HOME/profiles/desktop`，命令行**不能**管理这套桌面专用配置。

不发布 Linux 桌面安装目标（以当前 Desktop 文档为准）。

### 部署方案（终端用户）

1. 从官网下载站获取安装包（生产域名 `https://download.deepseek.com`；测试环境另有 `download-test`）。  
2. 安装并启动应用。  
3. 在应用内配置模型密钥（与网页版同类设置）。  
4. 应用可检查并安装更新（自动更新通道名固定为 nightly 一类策略，见 Desktop README）。  

### 部署方案（发版方 / 运维）

1. 在仓库用 Desktop 打包脚本打出各目标安装包（如 `mac-arm64`、`mac-x64`、`win-x64`）。  
2. macOS 公证；Windows 做 EV / Authenticode 签名（见 `apps/desktop/README.md`）。  
3. 把安装包与更新清单上传到 **腾讯云 COS**；对外用 `download.deepseek.com`（或测试域名）提供下载。  
4. 更新清单路径形如 `dsh-desk/feeds/<目标>/`；安装包在 `dsh-desk/bin/<目标>/`。  

依据：`apps/desktop/README.md`、架构文档 Desktop 一节。

### 云端关系

| 方向 | 内容 |
| --- | --- |
| 本机 → DeepSeek API / 可选遥测 | 与 A **相同**（做任务时的模型与可选上报） |
| 本机 → `download.deepseek.com`（或测试站） | **下载安装包、拉取自动更新** |
| 发版机 → 腾讯云 COS | **仅发版流水线**上传制品；用户日常使用不直接操作 COS |
| DeepSeek 账号登录体系 | **不是**桌面运行的前置条件（更新站是文件分发，不是 SaaS 控制台） |

## D. 无界面一次性任务（headless）

### 这是什么

命令行跑完一个任务就结束，**不开**网页服务、不监听给浏览器用的端口。适合脚本、CI、批处理。

### 部署方案

1. 安装方式同 A（npm）或 B（源码）。  
2. 配置好 `DEEPSEEK_API_KEY`（或其它提供方）。  
3. 运行例如：

```sh
dsh --profile headless "总结当前目录"
# 也可用 stdin、--json、--session-id 等（见 headless / CLI 说明）
```

依据：`packages/bundle/headless/README.md`、`apps/cli/README.md`。

### 云端关系

与 **A 的共用底座云触点相同**（模型 API、默认会话日志上传、可选遥测）。  
**没有**桌面那种更新站 / COS 关系；升级仍靠 npm 或源码。

---

## E. SDK 嵌入（TypeScript / Python）

### 这是什么

你的程序当「宿主」，通过 SDK **再启动一个** `dsh --profile sdk`（或最小版 `sdk-minimal`）子进程，用标准输入输出上的 JSON-RPC 对话。不是在 Python/TS 进程里嵌一整套插件树。

### 部署方案

**TypeScript：**

1. 依赖 `@deepseek-ai/dsh-sdk-client`，并保证同版本的 `@deepseek-ai/dsh` 可用。  
2. 创建客户端；首次调用时懒加载拉起 runtime。  

**Python：**

1. `pip install deepseek-harness-sdk`（会带上对应平台的 runtime 安装包）。  
2. **必须显式指定** Harness home（`DSH_HOME`）；默认不偷偷用 `~/.dsh`。  
3. 最小示例可选 `sdk-minimal` profile。  

注意：Python 安装包里仍可能带有网页资源，但「给 SDK 当服务」和「再跑 `dsh web`」是两件事；网页不能替代 SDK 的 stdio 协议。见 `docs/user/guide/python-sdk.md`、`python/README.md`。

### 云端关系

| 子形态 | 云端关系 |
| --- | --- |
| `sdk`（常用） | 与 A 类似：走共用底座 → DeepSeek API、默认会话日志上传、可选遥测等 |
| `sdk-minimal` | 更瘦的独立树：仍默认可带 DeepSeek 会话日志上传；**没有**完整底座里的 OTel、托管凭证、部分 Web/子 Agent 等 |
| 包分发 | TS 走 npm；Python 走 **PyPI**（另有 GitHub / GitLab 发版流水线） |
| 更新站 / COS | **不参与** SDK 运行时更新（除非你额外装桌面） |

---

## F. ACP 自动化

### 这是什么

以 ACP（Agent Client Protocol）方式对外：本机跑 `dsh --profile acp`，标准输出专供协议消息。由支持 ACP 的客户端发 `session/new`、`prompt`、`session/close` 等。

### 部署方案

1. 安装同 A 或 B。  
2. 启动：`dsh --profile acp`。  
3. 用 ACP 客户端对接 stdio。  

依据：`packages/bundle/acp-app/README.md`、架构文档。

### 云端关系

与 **共用底座**相同（模型 API、默认会话日志上传、可选遥测）。  
**没有**单独的「ACP 云控制面」；升级同 npm / 源码。

## 变体：SSH 远程开网页（仍算网页部署）

### 这是什么

在**远端机器**上跑 `dsh web`，你在**本地**用 SSH 端口转发打开浏览器。检测到 SSH 会话时，CLI 往往**不会**在远端自动弹浏览器，而是打印环回地址，由你在本地转发后打开。

### 部署方案（示意）

1. SSH 登录到远端，按 A 或 B 装好并启动 `dsh web`（仍监听远端的 `127.0.0.1`）。  
2. 本地做端口转发，例如把远端 `3080` 转到本机。  
3. 本机浏览器访问转发后的地址。  

### 云端关系

- 与网页版相同：远端进程 → DeepSeek API / 可选遥测。  
- **额外**：你与远端之间是 SSH（你自己的服务器或跳板），**不是** Harness 提供的云主机产品。  
- 官方入口仍**拒绝**把服务绑到 `0.0.0.0` 直接暴露公网。

## 总览图（部署位置 × 云端）

```text
                    ┌─────────────────────────────────────┐
                    │  DeepSeek 云（模型 API / 可选遥测）   │
                    │  桌面专用：download*.deepseek.com     │
                    │           （背后 COS 发版）           │
                    └──────────────▲──────────────────────┘
                                   │ 出站 HTTPS（密钥在本地）
     ┌─────────────────────────────┼─────────────────────────────┐
     │                             │                             │
┌────┴────┐  ┌────┴────┐  ┌───────┴──────┐  ┌────┴────┐  ┌────┴────┐
│ A/B 网页 │  │ C 桌面  │  │ D 无界面任务 │  │ E SDK   │  │ F ACP   │
│ 本机Node │  │ Electron│  │ 本机 CLI     │  │ 子进程  │  │ stdio   │
└────┬────┘  └────┬────┘  └──────────────┘  └─────────┘  └─────────┘
     │            │
     │            └── 另拉更新站（仅桌面）
     │
     └── 变体：进程在 SSH 远端，浏览器在本地（仍是网页）
```

## 怎么选

| 你的目标 | 更合适的形态 |
| --- | --- |
| 尽快在本机用界面 | A（npx）或 C（桌面） |
| 改代码、做 fork | B（源码） |
| 脚本 / CI 跑一次任务 | D（headless） |
| 嵌进自己的 TS/Python 程序 | E（SDK） |
| 对接 ACP 生态客户端 | F（ACP） |
| 代码在服务器、界面在笔记本 | A/B + SSH 端口转发（变体） |
| 要公网多用户 SaaS | **本产品不提供**；需自研，且勿误用被拒绝的 `0.0.0.0` 当「官方支持」 |
