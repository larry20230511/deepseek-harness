# DeepSeek Harness 脚手架分析报告

> 阅读日期：2026-09-21  
> 范围：本仓库作为 DeepSeek Harness fork 的**脚手架与启动模型**（如何组装、如何启动、如何扩展），非逐功能产品说明书。  
> 性质：解读笔记；事实以源码与权威文档为准。主要依据：`docs/architecture.md`、`docs/cordis-primer.md`、`packages/README.md`、`packages/boot/app-boot/README.md`、`vendor/README.md`、根 `package.json` / `pnpm-workspace.yaml`。

## 一句话结论

DeepSeek Harness 是一个 **everything-is-a-plugin** 的 pnpm monorepo：能力落在 `packages/<group>/<pkg>/`，运行时由 **命名 profile → 有序 bundle patch → 用户/CLI overlay** 在空插件树上叠层组成；**唯一受支持的 Node 应用入口是 `dsh --profile <name>`**（或 `dsh <name>`），不是各包自带的 bin、demo 或 SDK 内嵌第二棵 Cordis 树。

## 1. 顶层目录：谁拥有什么

| 目录 | 职责 |
|---|---|
| `packages/` | 全部 `@deepseek-ai/dsh-*` 能力包；路径固定为 `packages/<group>/<pkg>/` |
| `apps/` | 产品装配层：`cli`（`dsh` bin）、`web`（前端资产/测试）、`desktop` + `desktop-host`（Electron） |
| `vendor/` | 源码 vendored 的 Cordis 与基础库（可审计、可打本地补丁、`@deepseek-ai` 重命名） |
| `python/` | Python SDK + runtime wheel；默认起 `dsh --profile sdk` |
| `native/` | 原生能力（如 Landlock launcher、platform packages） |
| `scripts/` | 构建、门禁、catalog 生成、release；`run-gates.ts` 聚合 CI |
| `docs/` | 架构 / cookbook / 子系统参考 / 用户文档；生成物有 freshness gate |
| `.agents/` | `notes/` 决策记录、`skills/` 可复用工作流 |
| `website/` | VitePress **投影器**：不存权威正文，从 `docs/` 按 allowlist 投影 |
| `snapshots/` | **仅** session 驱动录制回放；进程必须经 `dsh` + shipped profile |
| `benchmarks/` | 性能门禁与依赖闭包 |
| `patches/` | pnpm `patchedDependencies`（如 node-pty、electron 相关） |

Workspace 成员见 `pnpm-workspace.yaml`：`vendor/*`、`packages/*/*`、`native/system(+packages)`、`apps/*`、`website`、`benchmarks`、`python/sdk-runtime`。引擎要求 Node `^22.19 || >=24`，包管理器 `pnpm@11.7.0`。

## 2. 组合轴心：Profile / Bundle / Patch

### 2.1 概念栈

运行中的 `dsh` **不是**写死的单体进程，而是 boot 时按层组成的插件树：

```text
空 entry 列表
  → 按 profile 的 dsh.profile.bundles 顺序应用各 bundle 的 cordis.patch.yml
  → 该 profile 目录下的 cordis.patch.yml
  → $DSH_HOME/cordis.patch.yml（home 级，覆盖 profile 级）
  → CLI --patch overlays
```

要点（见 `docs/architecture.md`、`packages/boot/app-boot/README.md#profiles`）：

- **Profile**：命名组合，落在 `$DSH_HOME/profiles/<name>`；含 `package.json`（声明 bundles）与用户 `cordis.patch.yml`；可装 out-of-tree 插件。
- **Bundle**：可分发的 patch 层 + 其依赖的代码；在 `package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`（例：`packages/bundle/base/package.json`）。
- **Patch 语义**：按 **id** 整段替换该行 `config`，或 `insert` 新行；**不做 deep-merge**。`!!js` 仅在 entry 的 `config` / `disabled` 上求值（`docs/cordis-primer.md` Loader Configuration）。
- **预览**：`dsh --profile web --dump-config` / `--dump-default-config` 打印将要挂载的树，而不真正启动业务。

### 2.2 出厂 profile 与 bundle

| Profile | 典型栈 | 说明 |
|---|---|---|
| `web` | `dsh-base` + `dsh-web-app` | 浏览器应用；默认端口等由 web 面配置 |
| `headless` | `dsh-base` + `dsh-headless` | 一次性 runner，无 server |
| `sdk` | `dsh-base` + `dsh-sdk-app` | JSON-RPC SDK server |
| `acp` | `dsh-base` + `dsh-acp-app` | 自动化-only ACP（stdio） |
| `sdk-minimal` | **仅** `dsh-sdk-minimal` | 故意不加 base；完整显式 SDK 树 |
| `desktop` | Electron **保留名** | CLI **不能** boot/管理；见 `apps/desktop` |

`dsh-base`（`packages/bundle/base/cordis.patch.yml`）是 web/headless/sdk/acp 的共享第一层：模型、工具、持久化、沙箱、settings、credentials、HMR/plugin-manager 等。模式差异行不进 base（避免多处 restatement 冲突），由各 mode bundle 整段重写。

静态组成图可由 `apps/cli/composition.md`（`gen-doc-graphs`）对照阅读。

### 2.3 启动链（源码路径）

1. 根脚本：`"dsh": "node --import tsx/esm apps/cli/src/bin.ts"`（根 `package.json`）——源码启动走 tsx ESM hook。
2. `apps/cli`：解析 argv，按所选 runner 加载；发布后 bin 为 `@deepseek-ai/dsh` → `lib/bin.js`。
3. `dsh-app-boot`：分层 `.env`、compose bundles/patches、挂 Loader、审计 **required** entries；失败则整树 dispose 并以非零退出。
4. `dsh-cmdline`：launcher 之后的参数交给 app（`ctx.cmdlineArgs` / `appReady` / `appExit`）。

Required 启动审计覆盖共享 Agent 执行与各应用端点（如 `agent-loop`、`webserver`、`headless-runner`、`acp`、`sdk-jsonrpc-server` 等，详见 app-boot README）。可选插件失败只告警；必选失败停启动。

硬规则（`docs/architecture.md#application-launch`，门禁 `scripts/verify-application-entrypoints.ts`）：

> **Only `dsh` profiles launch supported Node apps.**  
> package bins、demos、直接 in-process mount、私有 WebWorker preview 都不是 Harness 应用 launcher。

## 3. 包脚手架约定

### 3.1 命名与落盘

- npm：`@deepseek-ai/dsh-<name>`；vendored 亦 `@deepseek-ai/*`（映射见 `docs/rescope.md`）。
- 磁盘：`packages/<group>/<pkg>/`；**一包一组**；新包进已有组（`packages/README.md`）。
- 每个 harness 包以 `@deepseek-ai/cordis` 为 peerDependency（+dev）。

### 3.2 角色类型

| 类型 | 特征 | 例 |
|---|---|---|
| Plugin / service | Service 类 default-export，或 function 插件导出 `name`/`inject`/`Config`/`apply`（勿混用） | 多数能力包 |
| Library | 被 launcher/embedder 调用，无产品 bin | `dsh-app-boot` |
| Bundle | 主要交付 patch，不挂独立产品服务 | `dsh-base` |
| Capability family | Definition / Provider / Consumer 拆包 | `fs/`、`shell/`、`llm/` |

注册模型（根 `AGENTS.md`、`packages/AGENTS.md`）：

- **Registrations are effects**：`ctx.effect()` / `ctx.on()`；`register()` 返回 disposer。
- 依赖用 `inject` 声明，而非手写 boot 顺序。
- 可选服务用 `ctx.get(name)`；已 inject 才用 `ctx.<name>`。
- 扩展插件依赖 **Service Definition**，不依赖具体 Provider；`dsh-agent-loop` 可替换。

### 3.3 包内工程约定

- `tsconfig`：`tsconfig.base.json`（Client 用 `tsconfig.base.client.json`）；`rootDir: src` → `outDir: lib/types`。
- Host/Client 双面：叶子 `tsconfig.host.json` / `tsconfig.client.json` + solution-only root。
- 测试在包级 `tests/`，不在 `src/__tests__/`。
- 产品可见插件需要 **REAL composition** 测试（Loader + `cordis.yml`），禁止只手搓 `ctx.plugin(...)` 冒充集成。

组地图见 `packages/README.md`（core、llm、fs、shell、host、client、bundle、boot、sdk、acp…）。

## 4. 应用启动面

| 表面 | 路径 | 启动方式 |
|---|---|---|
| CLI / dsh | `apps/cli` → `@deepseek-ai/dsh` | **唯一公共 Node launcher** |
| Web | Host：`packages/host/*`；Client：`packages/client/*`；装配 `dsh-web-app`；资产/测试 `apps/web` | `dsh web` / `--profile web` |
| Desktop | `apps/desktop` + `apps/desktop-host` | Electron RunAsNode → 共享 profile runner + 完整 Web；独占 `$DSH_HOME/profiles/desktop` |
| Boot glue | `packages/boot/{app-boot,cmdline,hmr,plugin-manager}` | 库/服务，不是独立产品 bin |
| TS SDK | `packages/sdk/{protocol,client,server}` | Client **spawn** `dsh --profile sdk`（+patches） |
| Python SDK | `python/sdk` + `python/sdk-runtime` | wheel 内嵌 `dsh`；默认 `sdk`，最小例 `sdk-minimal`；须显式 Harness home |
| ACP | `packages/acp` + `dsh-acp-app` | `dsh --profile acp` |

Desktop 与 CLI **共享** `$DSH_HOME` 产品数据，但 **不共享** 可执行包、激活选择、lockfile。公共 CLI 不能管理 Desktop 的 profile。

## 5. 构建与测试工具链

### 5.1 构建面孔

- `build:lib:host`：`tsc -b tsconfig.host.json` + `tsdown --env.DSH_BUILD_FACE host`
- `build:lib:client`：`tsc -b tsconfig.client.json` + tsdown client
- 总构建：`tsx scripts/build.ts`；原生：`build:native-system`
- 源码启动：`node --import tsx/esm`（ESM-only；Node 原生 TS 模式不覆盖 engines 全范围）

### 5.2 测试分层（根 `AGENTS.md` / `docs/testing.md`）

| 命令 | 用途 |
|---|---|
| `pnpm run test` | 单元（vitest + native） |
| `pnpm run test:coverage` | **CI 覆盖率门**（非普通 `test`） |
| `pnpm run test:e2e` | 真 API；无 `DEEPSEEK_API_KEY` 自跳过 |
| `pnpm run test:expected` | owner-local 进程期望输出 |
| `pnpm run test:snapshot` | keyless 录制 session 回放（经 shipped profile） |
| `pnpm run test:docs` / `doc-sync` | 文档快速检查 / 全量文档门 |
| `pnpm run hygiene` | publint、workspace/依赖、NodeNext consumer 等 |

Snapshot 约定（`snapshots/AGENTS.md`）：只放 session JSONL 回放；必须 `dsh` + shipped profile；不新增旁路 entrypoint；修 fixture 不修 normalizer。

推送前按 `.agents/skills/dsh-pre-push-checks` 只跑相关证据面；不默认全仓套件。

## 6. 扩展模型：不改 agent-loop 的默认路径

### 6.1 Capability seam

完整缝 = **Service Definition + Service Provider + Consumer**（常为 model-facing tool）。换一个 provider 可带走整条能力链（例如远程 sandbox → Bash / PTY / LSP 一起走）。见 `docs/architecture.md` Capability seams、`docs/capability-seams.md`。

### 6.2 事件域

| 域 | 用途 |
|---|---|
| Session events | 持久事实；`session/event`；**model-visible ⟺ logged** |
| Agent events (`agent/*`) | 飞行中观察/拦截 |
| Capability events (`fs/*`, `tools/*`, …) | 策略/适配，不 import loop |

Waterfall（`agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre|execute|post-execute`）：监听者必须调用 `next()`，否则短路。Turn 流见 `docs/architecture.md` Turn flow。

### 6.3 新行为挂哪

| 目标 | 机制 |
|---|---|
| 新模型 | `ctx.llm` adapter |
| 新工具 | `ctx.tools` |
| 改单会话能力集 | agent preset + `isolate` |
| Shell / PTY / FS / sandbox / jobs / webhook | 对应 `ctx.*` + 事件 |
| 拦截请求/工具/turn | `agent/*` / `tools/*` |
| 持久状态 | 扩展 `SessionEventMap` |
| UI | `ctx.agents` + `session/event`；Client ConversationNode |

**禁止默认改 `agent-loop`**：新行为走扩展点；改 loop 必须同步更新 `docs/architecture.md`。操作手册入口：`docs/cookbook/extension-cookbook.md`。

## 8. Fork / 定制视角：本仓特化点

相对「上游 Cordis 原样 + 普通 monorepo」，下列点高度本仓特化，fork 时优先摸清：

1. **重度 vendored Cordis**（`vendor/README.md`）：fiber 生命周期加固、`applyEntryPatches` 导出、lazy config、`disabled: !!js`、Node 24 loader 形状检测、`@deepseek-ai` rescope 等。同步上游必须重放该日志。
2. **Profile/bundle 启动模型**是产品轴心；`verify-application-entrypoints` 强制「只有 dsh」。
3. **Desktop 双轨**：保留 `profiles/desktop`、独立 runtime/lock，与 CLI 隔离——勿与 CLI profile 混装。
4. **DeepSeek 产品行**挂在 base 组成里（如 `deepseek-llm-api-extensions` 等）——白标/去品牌需从 bundle patch 层处理。
5. **双 SDK 同协议**：TS + Python 都是「起 dsh profile」，不是嵌入另一棵 Cordis 树。
6. **文档/Agent 操作系统**：预算门、双语 pairing、Agent Note 生命周期、skills——砍掉 gates 后文档会很快漂移。
7. **Host/Client tsconfig faces + tsdown**：GUI 与共享类型是一等构建面。
